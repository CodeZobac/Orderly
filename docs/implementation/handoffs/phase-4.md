## Implemented capabilities

- `/billing`: local calendar period (inclusive start, exclusive end) and client/project filters; exact unbilled intervals, separate currency totals, billable/non-billable durations, task subtotals and source/confirmed-PR evidence. Manual/non-code work needs no PR. Saved report list, immutable finalized view, historical voided view, CSV download and print stylesheet with evidence URLs/status.
- Audited entry-rate override with reason, source-entry optimistic revision and before/after entry history; project defaults do not rewrite entry rates. Running entries, invalid intervals/rates and inconsistent/unsupported currencies block finalization. Zero is a valid explicit rate. Entries exceeding twelve hours require explicit acknowledgment at finalization.
- Draft → finalized → void. Finalization re-reads and compares the whole draft snapshot; changes require explicit refresh/review. One owner-row lock serializes tracker/billing mutations, retry keys are durable, and allocation overlap is rejected under that lock. Half-open millisecond ranges subtract prior active allocations; adjacent periods cannot bill the same milliseconds. Both billable and non-billable reviewed allocations are retained and excluded from later drafts.
- Finalized snapshots store filters/timezone, effective rates/currency, source entry ID/revision/full interval, allocated interval, labels, notes, exact monetary numerator/denominator, apportioned minor amounts, evidence URLs and rounding policy. Entry edits/delete/restore/rate changes are blocked while any active allocation uses it. Void all affected reports with reasons before editing; snapshots and allocation/audit history survive void. Create a new draft to reissue; previously downloaded copies require separate recipient notification.
- Exact SQL `numeric` calculations: rates are hundredths of currency units/hour, not necessarily ISO minor units. Sum exact amounts per currency, round half up once to ISO minor-unit precision; distribute the rounded total among lines using largest remainder (ties by entry ID/start). CSV line amounts and task subtotals therefore sum to the same currency total. No time rounding or conversion. Numeric amounts travel as strings and use BigInt formatting in UI/CSV. Currency table is frozen from SIX ISO 4217 publication 2026-09-17; unknown/nonmonetary codes block billing. Historical snapshots retain their own precision.
- Formula-injection protection for CSV cells, including leading whitespace/control characters; untrusted URLs are HTTPS-only links. Exports use the saved snapshot, not current provider metadata. Draft/void status stays prominent. Reports are work evidence, not tax invoices.
- Settings on-demand durable monitoring: owned source status, last success, retry count, eligible time and lease expiration; no credentials or lease tokens. Offline release environment syntax validator prints only field names/issues.

## Architecture and migration

- `source/supabase/migrations/20261010115311_phase_four_billing.sql` generated by the installed Supabase CLI. Adds private `billing_batches`, `billing_allocations`, `billing_audit`, ownership FKs/indexes/RLS, immutable/entry/allocation guards, ISO precision helper, transactional review/finalization RPC `orderly_billing`, and owned read-only `orderly_operations`. Uses PostgreSQL multiranges (PG14+), no new extensions, compatible with one migration transaction. Review/source snapshot is computed by SQL, never supplied by the browser.
- All functions SECURITY INVOKER, empty search_path; anon/authenticated/PUBLIC privileges revoked; service_role-only access. Independent Orderly sessions remain the authentication boundary. No Supabase Auth added. `lib/billing.ts`, `billing-types.ts`, `billing-format.ts` own API validation/contracts/exact presentation.
- `GET /api/billing`: owned index/audit, `?id=` returns a saved batch. `POST`: `preview`, `draft`, `refresh`, `finalize`, `void`, `rate`, same-origin session authenticated. Mutations require retry key; report writes require expected version. Finalize requires `reviewedLong` entry IDs. `GET /api/billing/export?id=` downloads owned CSV; `GET /api/operations` returns owned monitoring. All responses no-store.
- `components/billing.tsx`, `operations.tsx`; tracker navigation and route whitelist mount the new view; `app/globals.css` appends ledger/print styles. Existing amber colors, fonts, native control states/focus and reduced-motion system preserved. Source review shortened mobile action labels and reuses named tokens. No new rendered visual or contrast evidence is claimed.
