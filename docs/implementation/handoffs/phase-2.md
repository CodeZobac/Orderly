# Phase 2 — Asana and Notion handoff

Status: **implemented locally; acceptance verification and live activation pending** (2026-10-10). Phase 2 remains partial until its database/provider/browser acceptance checks are authorized and completed. Do not advance automatically to Phase 3.

## Delivered

- Asana OAuth authorization-code flow with S256 PKCE; Notion public OAuth with API version `2026-03-11`. Callback state is random, hashed in PostgreSQL, bound to the initiating browser and still-active independent Orderly session, expires after ten minutes, and is consumed once. A separate HttpOnly Lax callback cookie leaves the Orderly session cookie Strict.
- Server-only AES-256-GCM encryption for access tokens, refresh tokens, OAuth verifiers and Asana webhook signing secrets. UI snapshots exclude credentials and lease tokens. Refresh-token rotation is serialized across discovery and background work with connection leases.
- Paginated Asana workspace/project discovery and task imports, including completed tasks, completion/section status, assignee, due date and provider URL. Section labels can be mapped with `section ID = status` lines.
- Notion accessible data-source discovery, explicit schema inspection, required title and optional status/select, people and date mappings. Stable property IDs survive renames; missing/incompatible properties stop sync with a remapping message. A database container is not treated as a task board.
- Connection-scoped external IDs and canonical task links; titles never cause cross-provider merging. Multi-home Asana tasks are held for an explicit billing assignment. A later multi-home change blocks new timer/manual attribution until confirmation. Explicit linking is available in Settings before recording time; time-bearing tasks cannot be reassigned by integration linking. Local task labels on explicit links stay local.
- Durable page checkpoints, event dedupe, three-minute fenced worker/connection leases, per-installation serialization, retry/backoff/jitter, `Retry-After`, manual resync and fifteen-minute reconciliation. Events trigger fresh source reads rather than trusting stale event contents. An event arriving during a scan requests a follow-up scan.
- Authenticated Asana webhook handshake with provider-response secret comparison; signed raw-body Asana and Notion event handling. Accepted events and jobs commit before acknowledgement. Asana webhook renewal is explicit; retired callbacks return 410. Notion subscription verification is configured manually in its developer portal.
- Settings connection/source mapping and recovery UI; unified canonical task list with provider/status/unavailable badges and existing timer actions. Archives, removals, access loss and disconnect retain canonical tasks, entries, rate snapshots and last imported labels. Imports never insert or alter time entries; an entry trigger only validates new ambiguous attribution.

## Architecture and contracts

- `source/supabase/migrations/20261009235442_phase_two_integrations.sql`, generated by installed Supabase CLI: `connections`, `oauth_states`, `sources`, `external_tasks`, `source_tasks`, `sync_jobs`, `sync_events` in `orderly_private`. Composite ownership foreign keys; RLS enabled; no public/anon/authenticated grants. New public RPCs are SECURITY INVOKER with empty search paths and service-role-only execution. Snapshot and timer helpers extend the foundation without replacing independent authentication.
- `source/lib/providers.ts`: fixed provider hosts, normalization, source/schema discovery, one-page imports, token exchange/refresh, safe error classification. Adapter calls return `{tasks,cursor}`; the worker owns persistence and retry. Notion version is pinned in `NOTION_VERSION`.
- `source/lib/integration-crypto.ts`, `integration-types.ts`, `integrations.ts`: encryption, shared public types, ownership-scoped orchestration and one-page `workOnce`.
- `source/scripts/sync-worker.ts`: separate long-running process, graceful SIGINT/SIGTERM; `--once` processes at most one due page. Next does not start the worker automatically. Deploy it on a persistent worker host with the same database and encryption environment as the app.
- `GET /api/integrations`: owned public connection/source/task/membership snapshot. `POST`: `discover`, `inspect`, `map`, `resync`, `link`, `disconnect`, `webhook`. Mutations and discovery require an authenticated session and exact Origin. Client owner IDs are ignored.
- `POST /api/integrations/{asana|notion}/connect`: returns authorization URL and sets callback cookie. `GET .../callback`: verifies browser state, consumes the durable state, exchanges code and stores encrypted credentials; redirects to Settings. `POST .../webhook`: provider-specific raw-body verification and durable receipt; never accepts browser ownership claims.
- A source remap increments its generation and retires old jobs. Connection reconnect/disconnect increments its generation; old worker completions cannot overwrite new state. UI discovery leases exclude worker refresh, and worker leases exclude discovery refresh. Owner → connection → source → job locking order is used for mutations/completions.
- Imported metadata changes canonical names only for auto-created links. Project mapping changes affect new imports, never move existing tasks/entries. Explicit linking does not combine durations or rates. Source membership absence is marked only after a complete successful scan, so partial failure does not erase historical context.
- Synchronization deliberately uses paginated current-state source scans for both event hints and reconciliation, with incremental local upserts. It does not depend on provider change cursors or optimize events to single-object fetches. Persistent event/job tables currently have no automatic archival policy; assess retention and scale during release readiness.

## Setup

Run application commands in `source/`. Deploy the new migration through the Supabase GitHub integration for `CodeZobac/Orderly` (working directory `source`, production branch `main`), alongside the existing foundation migration. No direct live migration was applied here. Integration enablement/deployment is still unverified; require the preview check before merge when configured. Keep independent Orderly authentication.

Configure server-only values from `.env.example`:

- `SUPABASE_URL`, `SUPABASE_SECRET_KEY`: existing private RPC access. A local secret value is present, but its validity and the deployed schema were not queried in this session.
- `ORDERLY_ORIGIN`: exact public HTTPS origin. Asana requires a registered HTTPS callback, including development via an HTTPS tunnel.
- `ORDERLY_INTEGRATION_KEY`: generate with `openssl rand -hex 32`, store in ignored environment/deployment secrets, and share unchanged between app and worker. Losing/changing this key requires reconnecting providers. Do not prefix secrets with `NEXT_PUBLIC_`.
- `ASANA_CLIENT_ID`, `ASANA_CLIENT_SECRET`: register `${ORDERLY_ORIGIN}/api/integrations/asana/callback`. Approve `projects:read tasks:read workspaces:read users:read webhooks:read webhooks:write webhooks:delete`; configure app distribution for the workspaces that will authorize it. Task/status/time writeback scopes are not requested.
- `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET`: public integration, registered `${ORDERLY_ORIGIN}/api/integrations/notion/callback`, read-content capability and appropriate user information access. Share the chosen database/data sources with the integration during authorization.
- `NOTION_WEBHOOK_VERIFICATION_TOKEN`: create a webhook subscription targeting `${ORDERLY_ORIGIN}/api/integrations/notion/webhook`, enable relevant page/data-source lifecycle and property events, configure `NOTION_WEBHOOK_SETUP_OWNER_ID` using your account ID displayed in Settings and redeploy. Start temporary verification capture in Settings, update the unverified subscription to the generated URL and resend the token. Explicitly retrieve the encrypted, session-bound token, confirm it in Notion, and set it in the server environment before redeploying. Clear the capture afterwards. Normal events require the token's `sha256=` HMAC signature and ignore the setup query. Keep the verified URL. Capture expires after ten minutes and accepts only the first delivery; routine responses and logs never expose it. Apply `20261010113155_notion_webhook_setup.sql` through GitHub deployment first. See source README for the full procedure.

Start the app with `npm run dev`, or `npm run build` then `npm start`. Start the independent worker with `npm run sync:worker`; supervisor restart is recommended. `npm run sync:worker -- --once` performs one due page and exits. In Settings connect providers, choose sources and billing projects, map Notion properties, then enable/renew Asana project webhooks if desired. Refresh sync status to see worker progress and imported tasks.

Actual local configuration inspection found `ORDERLY_ORIGIN`, the encryption key, both provider client IDs/secrets and the Notion verification token absent. No OAuth/provider/webhook live flow was attempted.
